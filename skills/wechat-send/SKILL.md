# 通用微信发消息规范（wechat-send）

本 Skill 通过 `HIDAGENT_SKILLS` 优先挂载到底座服务端，作为通用微信发消息的策略、频控、熔断词与操作避坑边界。**所有坐标均由当前帧动态识别计算，不提供也不允许使用写死的静态 `layout.json`。**

## 1. 目标限制（M1 验收阶段）

- M1 初期**只允许**向白名单会话（默认仅 `文件传输助手`）发送消息。
- 严禁向任何真实个人联系人或真实微信群发送消息，除非经人工显式扩展配置白名单并获明确授权。
- 默认运行模式为 `--dry-run`（完成粘贴与文本核对后立即停在发送前）；只有显式传入 `--send` 且通过全部守卫检查时，才执行单次发送。

## 2. 禁止发送的内容

- 验证码、登录密码、银行卡号、支付口令、红包/转账信息。
- 身份证号、手机号等个人隐私敏感信息。
- 政治、医疗诊断、法律承诺、投资建议或未经当前屏幕依据核实的事实。
- 不可控的多字节表情符号（`paste-flow` 仅按精确原文粘贴，若当前业务不允许则禁止输入）。
- 空消息或纯空白字符。

## 3. 系统熔断与频控守卫

- 发送前必须调用 `skill-check`，将当前屏幕可见提示文字传入检测。基础停词（`操作频繁`、`风控`、`验证码`）与 `extra_stop` 任一命中导致 `stop: true` 时，**立即停机且严禁重试**。
- 仅在完成粘贴核对、准备点击发送前，调用 `skill-prepare-send` 核对静默时段与频控上限并占取 30 秒一次性发送名额（`allowed: false` 立刻停机）。
- 只有在新画面中明确看到**完整的右侧新绿色消息气泡**时，才调用 `skill-confirm-send --bubble-visible` 结算。输入框清空或仅串口返回 `ok` **不代表发送成功**。

## 4. 已验证真机操作避坑清单

1. **打开微信**：当前桌面已经可以看到「微信」时，直接点击文字上方的**图标本体**（绝不点文字中心），不额外调 `search-app` 翻页；仅当当前屏幕确实没有微信图标时，才调 `search-app WeChat` 并点击结果图标本体。
2. **紧连原子点击链**：在会话列表等自动刷新区域及所有交互按钮上，必须使用 `point --target-box` → `observe --for-click` → `click-observed` 紧连执行，中间不得插入耗时 OCR 或等待，防止 iOS 在 3 秒内自动隐藏辅助触控指针。
3. **指针落点核对**：`point` 返回的 `measured_pointer` 必须是 JSON 对象 `{"x": ..., "y": ...}`（非数组）。必须确认其非空且严格落在 `--target-box` 内才推进；`click-observed` 严禁传入请求坐标或 OCR 文字中心。偏位时允许带 `--rehome` 重新定位。
4. **底部输入框瞄准**：点击收起态输入框时，瞄准白色输入区偏左文字起点区域，严格避开 `y > 0.95`（`x ∈ [0.32, 0.68]`）的 iOS 主屏幕指示条吸附区，并以「原生键盘弹出 + 输入框上移」确认聚焦。
5. **已有草稿保护**：若聚焦后输入框内已存在非空草稿，**原样保留并立即停机汇报**，严禁清空或覆盖。
6. **单次 `paste-flow` 与 `recovery_state` 停机**：使用 `0700` 私有目录下的 `payload.txt` 只调用一次 `paste-flow`。仅当 `cmd_v_sent == 1`、`phase == "completed"`、`effect_verified == true`、`recovery_state == "completed"` 才算粘贴完成。失败时严格按 `recovery_state`（`not_copied` / `claimed_not_confirmed` / `copied_not_pasted` / `paste_sent_unconfirmed`）停机汇报，禁止盲目重跑。
7. **蓝色发送按钮动态扩框与 409 重试边界**：
   - 基于右下键盘区域精确 OCR「发送」/「Send」文字框并结合蓝色按钮像素区域动态扩框，覆盖整个蓝色按钮本体，同时硬隔离左侧「空格」键。
   - 发送前 `point` 与 `click-observed` 显式透传已识别的完整白色输入框范围 `--caret-scope`（配合底座 120 秒自动延续策略形成双保险），容忍输入框内绿色光标闪烁，同时仍严格拦截发送按钮之外的真实画面变化。
   - 点击前 `point` 遇光标闪烁 HTTP 409 时，仅允许重试 `observe → point` 移针（绝不触发点击）。
   - 发送时的 `click-observed --target-label 发送`（或 `Send`）最多执行一次，任何失败或异常都**严禁重试点击**，必须重新观察确认。
